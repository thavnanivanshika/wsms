How testing works: All tests are unit tests — they test one piece of logic in isolation. Instead of using a real database, we use Mockito to create fake versions of the database so tests run fast. AssertJ is used to check the results are correct.

File 2 — RequestServiceTest.java  (core business logic)
📝
Create a request successfully
createsSubmittedRequestWithLineItems()
✓ PASS
Setup
Employee has ₹5,000 budget. Requests 4 × Paper at ₹250 each = ₹1,000.
What it checks
Status = SUBMITTED. Total = ₹1,000. Email sent. History saved.
Why it matters
Proves the basic "happy path" — normal request creation works correctly.
📦
Block request when stock is not enough
rejectsWhenQuantityExceedsStock()
✗ Error expected
Setup
Stock has only 100 units. Employee requests 200 units.
What it checks
Error thrown: "exceeds available stock". No email is sent.
Why it matters
Without this check, employees could request more than what exists in inventory.
💰
Block request when budget is exceeded
rejectsWhenCostExceedsRemainingEligibility()
✗ Error expected
Setup
Only ₹500 left in budget. Request costs ₹1,000.
What it checks
Error thrown mentioning "eligibility". Request is blocked.
Why it matters
The ₹5,000 cap is the core rule of the system. This test proves it cannot be bypassed.
✅
Approving a request reduces stock
approveDecrementsStockAndSetsApproved()
✓ PASS
Setup
A submitted request for 4 × Paper. Stock = 100. Admin approves it.
What it checks
Status = APPROVED. Stock drops from 100 → 96.
Why it matters
Stock must reduce on approval, otherwise the same items could be approved for many people.
🚫
Cannot withdraw an already approved request
withdrawOnlyAllowedWhileSubmitted()
✗ Error expected
Setup
Request is already APPROVED. Employee tries to withdraw it.
What it checks
Error thrown: "awaiting approval". Withdrawal is blocked.
Why it matters
Employees cannot undo the admin's decision. They must use the cancellation flow instead.
🔄
Cancelling a request restores stock
confirmCancellationRestoresStock()
✓ PASS
Setup
Request was approved (stock at 96). Employee requested cancellation. Admin confirms.
What it checks
Status = CANCELLED. Stock restored from 96 → 100.
Why it matters
When a request is cancelled, the items go back to inventory — otherwise stock drains forever.
File 3 — ReportServiceTest.java  (analytics)
📊
Report calculates cost and percentage correctly
aggregatesCostHeadCountAndPercentagesOverApprovedLineItems()
✓ PASS
Setup
2 users, 2 items. Alice + Bob buy Paper (₹1,000 total). Alice buys Pen (₹500). Grand total = ₹1,500.
What it checks
Total = ₹1,500. Paper = 66.67%. Pen = 33.33%. Head count = 2.
Why it matters
Admin makes decisions based on reports. If the maths is wrong, the admin sees false data.
🗂️
One request with multiple items works correctly
multipleLineItemsInOneRequestAreAggregated()
✓ PASS
Setup
One request with 2 items: Paper×2 (₹500) + Pen×4 (₹200). Total = ₹700.
What it checks
Report has 2 lines. Total = ₹700. Head count = 1.
Why it matters
WSMS allows one request to have many items. Report must handle that correctly.
🕳️
Report is empty when no requests exist
emptyWhenNoApprovedRequests()
✓ PASS
Setup
Zero approved requests in the system (fresh install).
What it checks
Lines = empty. Total = ₹0. No crash or error.
Why it matters
The report page must not crash when there's no data — edge case protection.
